Page transitions

With page transitions, the links of the site load the next page into the element with the content of the page, the canvas, instead of loading the page in full. The header, the scripts and everything the page has loaded stay, so only the content of the next page and its pagelets are requested and rendered.

The server turns them on for a page by calling Quickling.init() with the canvas, see Quickling in the PHP library:

Quickling.init(document.getElementById('content'), {
  version: '2026-10-10',          // a page of another version is loaded in full
  inactivePageRegex: '^/admin',   // paths always loaded in full
  badRequestKeys: ['print'],      // query parameters that need a full load
  sessionLength: 50               // after this many page transitions the next page is loaded in full
});

Navigation​

PageTransitions takes over the clicks on the links of the page and the GET forms. A link is left to the browser when it goes to another origin, opens a new window (target), is a download, is handled by the Primer (rel="async", rel="dialog", ajaxify), has rel="external", or is clicked with a modifier key or another button than the main one. A link to a fragment of the current page only scrolls to it, and a link to an empty fragment of it, like href="#", does nothing.

PageTransitions.go(url) loads a page from JavaScript; PageTransitions.go(url, true) replaces the current history entry instead of adding one, as a redirect of the server does. The back and forward buttons load the page of the history entry and restore its scroll position, also for the entries other scripts added with history.pushState(); an entry of the same page with another fragment only scrolls to it. Every entry keeps its own scroll position, also in its history.state, so it is restored after a reload too.

When a page transition can't be used, the page is loaded in full: when the page must not be handled, the request fails, or the server sends a page of another version, e.g. after a deploy.

The request​

Quickling requests the URL with GET and the parameter quickling[version]. The server responds with an AsyncResponse whose payload has:

  • version: the version of the page, compared with the one of Quickling.init().
  • title: the title of the page, the title is kept without one.
  • body_class: the class of <body>, the class is kept without one.
  • redirect: a URL to go to instead, with a page transition, or in full with force.

Before the response is applied, the pagelets in the canvas are destroyed, Pagelet/destroy is informed with the canvas as root, and the canvas is emptied. Its DOM operations then fill the canvas (the element the request is relative to) and its pagelets are loaded like on a page. Only the response of the latest page transition is applied.

The request is streamed: a server that sends every pagelet as soon as it is rendered shows the next page progressively, like a page streamed with BigPipe::stream(). The page transition completes once the pagelets of the last part are displayed.

A new deploy​

The page keeps the scripts it was loaded with. When the server defines the revision of its deploy as the BigPipeRevision module (BigPipe::setRevision() in the PHP library), every response carries the revision of the server too. The first response of a newer deploy informs BigPipe/newRevision as a state, with the revision and the one of the page, e.g. to offer to reload, and the next page transition loads the page in full, with the new scripts:

new Arbiter().subscribe('BigPipe/newRevision', ({ revision }) => {
  showBanner('A new version is available.');
});

isOutdated() from bigpipe-util/dist/core/Revision tells it later.

Leaving a page​

A page that is left runs its leave hooks, its timers are cleared, and its requests in flight are abandoned unless they were sent with setAllowCrossPageTransition(true), see AsyncRequest:

import PageTransitions from 'bigpipe-util/dist/PageTransitions';
import { setInterval } from 'bigpipe-util/dist/core/TimerStorage';

setInterval(refreshTimes, 60000);  // cleared when the page is left

PageTransitions.addBeforeLeaveHook(() => (form.dirty ? 'You have unsaved changes.' : null));
PageTransitions.addLeaveHook(() => player.stop());

Run registers the same hooks and works for full page loads too: Run.onBeforeUnload() and Run.onLeave().

core/TimerStorage has setTimeout, setInterval, requestAnimationFrame and requestIdleCallback (with their clear and cancel functions) that end with the page, and setTimeoutAcrossTransitions, setIntervalAcrossTransitions, requestAnimationFrameAcrossTransitions and requestIdleCallbackAcrossTransitions for the timers that outlive it. The plain browser functions outlive the page too.

Events​

Informed through Arbiter, exported as PAGE_TRANSITION_EVENT from PageTransitions and QUICKLING_EVENT from Quickling:

EventWhen
PageTransitions/beforeTransitionBefore a page is left, with from and to.
PageTransitions/transitionA handler loads the next page, with its uri.
Quickling/unloadThe page is left for the next one.
Quickling/sendThe request for the next page is sent.
Quickling/firstResponseThe response is about to be applied.
Quickling/beforeClearCanvasThe canvas is about to be emptied.
Quickling/responseThe response was applied.
PageTransitions/beforeFragmentTransitionBefore a fragment of the same page is scrolled to, with the from and to fragments.
PageTransitions/fragmentTransitionA link to a fragment of the page was followed, with its fragment.

Handlers of other kinds of page transitions can be added with PageTransitions.registerHandler(handler, priority): a handler gets the URL and returns true when it loads the page.
